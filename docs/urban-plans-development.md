## 개발 단계

1. 초기 관련계획 구현: `feature/related-plans-20261111`, `8f051ac37ebf59caa72f8a66a867188b7ba88b3c`.
2. 서울 24개 계획·40개 링크의 독립 모듈 반영: `urban-analysis`, `572e0ddd0b04cdff29b43767fff762c21a42a219`.
3. 공통 화면 진입 버튼·서버 경로 연결: `urban-analysis`, `16c95cca5dd74c459ae2d8d5b34f3b8e24f75462`. 기존 계획조회 UI 유지, 관련 검사 37개 통과.
4. 경기도 첫 자료 확장: `urban-plans-gyeonggi`, `1f2929bc380c6dd578863865cb771fff584f53a8`. 50개 계획·62개 공식 링크, 검사 45개 통과.
5. 분야별 확장: 정비·노후계획도시·경관·공원녹지·도시재생·공업지역 계획 20개와 공식 링크 36개를 추가했다.
6. 전국계획 통합 개발 브랜치 `urban-plans`를 기존 `urban-plans-gyeonggi` HEAD `db8e7ed1`에서 생성하고 수도권 추가 계획 11개를 반영했다.

초기 경기도 자료 확장은 `urban-plans-gyeonggi`에서 수행했고, 2026-11-13부터 신규 `urban-plans`를 전국 관련계획 개발의 단일 브랜치로 사용한다. 기존 경기도 브랜치는 기록으로 남겨 둔다. 모듈 구현 파일명은 기존 `related_plans.py`를 유지한다.

저장소 이름은 `urban-strategy`를 유지한다. 기존 날짜형 브랜치를 삭제하거나 전체 이력을 병합하지 않는다. 관련계획 확장 작업은 `urban-analysis`와 `main`에 직접 반영하지 않는다.

## 경기도 확장 범위

- `plan_catalog_assets/gyeonggi-plans.json`: 경기도 전체 계획 6건, 31개 시·군 기본계획 공개본 31건, 후속 수립이력 12건, 분야별 계획 21건. 합계 70개 계획·98개 공식 자료 링크. 분야별 자료에는 도시·주거환경정비기본계획 5건과 1기신도시 5곳의 노후계획도시정비기본계획을 포함한다.
- `related_plans.py`: 서울·경기 초기자료를 함께 적재. 새 초기자료의 제목이 기존 사용자 등록과 충돌할 때 기존 항목을 보존하고 해당 초기 항목의 삽입을 생략한다.
- `tests/`: 기존 서울 24개·40개 링크 유지, 31개 시·군·일반구 조회, 상위지역 자료 상속, 페이지 구분, 수립상태·검색, 신도시별 일반구 조회 범위·집계, 부문계획 분류와 미확인 날짜 유지, SQLite 초기자료 추가와 사용자 이력 보존 검사.
- 관련 문서: 초기 모델과 확장 브랜치, 공식 자료의 확인 범위 및 미확인 사항 기록.

`app.py`, `app.html`, `dev_app.py`, `development-ui.js`, Dockerfile, 공통 의존성·기존 CI는 변경하지 않는다. 서울 도시정비 RULE, 공간 FACT, 건축물·도면 기능에도 개입하지 않는다. 구현 파일명과 `/plans`, `/api/related-plans` 경로, 기존 UI를 유지한다.

## 검증·반영 구분

API·앱 통합 검사 55개, Python 문법, 기존 계획조회 JavaScript 문법 및 공백 오류 검사를 실행한다. 경기도 확인 주소는 이 브랜치로 실행한 서버의 `/plans?region=41`이다.

GitHub 확장 브랜치 커밋과 운영 배포를 구분한다. Render의 연결 브랜치·웹훅·환경변수는 변경하지 않는다. PostgreSQL 운영 DB 및 브라우저 렌더링 재검사는 이번에 수행하지 않는다.

향후 통합 시 `urban-analysis`의 최신 변경과 충돌 여부를 확인하고 관련계획 변경분만 검토한다. 다른 창의 기초현황·건축물·도면 변경을 덮어쓰지 않는다. 초기자료는 추가 중심으로 적재하므로 이미 운영자가 수정한 계획의 상태·고시일은 자동 덮어쓰지 않으며 관리자 변경 이력으로 관리한다.

## 전국 확장 및 후속 urban-analysis 통합 원칙 (2026-11-13)

- 지역별 신규 브랜치를 반복하지 않고 단일 `urban-plans`에서 전국 자료를 확장한다.
- 기존 서울 24개 계획·40개 링크, 경기 70개 계획·98개 링크는 유지한다. `metro-plans-additions.json`에 수도권 공통계획·정비·재생·공업 계획 11개를 추가하여 총 105개 계획으로 구성한다.
- 제4차 수도권정비계획은 하나의 계획으로 등록하고 서울·인천·경기 3개 광역단위에서 공동 조회한다. 계획 적용의 법적 경계 판정 기능으로 사용하지 않는다.
- 재정비촉진지구별·활성화지역별 개별 계획은 전체 광역계획과 구분한다. 공식 고시, 변경 고시, 수립안 공청회 및 단계 미확인을 분리한다.
- 공업지역기본계획은 수립 대상 지자체를 추정해 가상 계획으로 추가하지 않는다. 공개 수립자료가 있는 지방자치단체만 실계획으로 등록한다.
- 운영 서버·PostgreSQL·브라우저 실제 실행 검증은 아직 수행하지 않았다. GitHub 커밋과 운영 배포는 별개다.
- 후속 `urban-analysis` 병합은 해당 브랜치 최신 변경을 보호하며 관련계획 모듈 파일만 선택 통합한다. 공통 FACT·도면·건축물·서울도시정비 RULE을 임의 수정하지 않는다.
