# v2.5.0 R21 단일 분석경계·저사양 순차분석 진단 (2026-08-31)

- 기준본: **R20**. 앱 버전은 **v2.5.0 유지**. 새 사업기능을 추가하지 않고 R20 실제 대상지 테스트에서 드러난 분석경계·백엔드 오류·도로 선행자료 문제를 우선 정리한다.
- 사용자가 지도에 그린 도형은 `입력 참고경계`로 남긴다. 연속지적에서 자동선정된 필지의 union을 후속 GIS의 **단일 분석경계**로 확정하며, 역세권·용도지역·도시계획·건축·도로·가로구역이 서로 다른 분모를 사용하지 않도록 한다.

- 정비사업 GIS·개발사업 GIS 등의 응답이 JSON이 아니면 HTTP 상태, Content-Type, 응답 앞부분을 진행상태에 남긴다. 작은 서버에서는 대형 정비/개발 공간색인을 요청 후 해제하도록 기본 설정했다.
- 도로·접도는 `TL_SPRD_MANAGE ROAD_BT`가 확보되지 않으면 실패로 끝낸다. 이 경우 노선형 상업지역과 가로구역은 긴 시간 대기하지 않고 선행자료 미확보로 즉시 종료한다.
- 도로 분석은 **VWorld `TL_SPRD_MANAGE` 도로중심선의 `ROAD_BT` 공식 폭원만 사용**합니다. 폭원 누락 구간은 추정하지 않고 REVIEW로 남기며, 접도연장·접도율은 초기검토용 개략값으로 현장조사·도로대장·결정도서에서 재확인합니다.
- 로컬 검증에서는 `/`, `/health`, 도로자료 진단, 정비사업 공간중첩, 개발사업 공간중첩이 JSON/HTTP 200으로 응답했고 전체 회귀검사를 통과했다. 실제 Render/VWorld 환경에서 같은 대상지 재검증이 필요하다.

# v2.5.0 R17 공간관계·도로 Fact 엔진 정리 (2026-08-31)

- 기준본: **R16**. 이번 수정은 `공간분석 Fact → 사업별 Rule 판정` 연결계층과 가로구역·접도 공통 Fact를 정리한다. 다른 사업의 정책기준을 일괄 재작성하지 않는다.

- 가로구역 관계값을 분모별로 분리한다: `대상지∩가로구역/가로구역`, `대상지∩가로구역/대상지`, `가로구역∩역세권/가로구역`, `대상지∩역세권/대상지`. 화면에도 분모를 생략하지 않는다.
- 역세권복합개발의 가로구역 1/2 판정은 **가로구역 중 사업대상지 점유율**을 사용한다. 역세권활성화의 가로구역 1/2 판정은 **가로구역의 적용 역세권 편입률**을 사용한다. 서로 같은 50% 값으로 취급하지 않는다.
- 도로 공통 Fact는 `TL_SPRD_MANAGE` 도로중심선의 공식 `ROAD_BT` 폭원을 사용하고, 접도도로별 도로명·폭원·접도연장·최대 연속접도·대상지 둘레비와 4/6/8/20/35m 임계값을 저장한다.
- 가로구역 후보는 SGIS 기초단위구를 골격으로 사용하고, 인접 기초단위구 공통경계에 `ROAD_BT >= 4m` 도로중심선 또는 철도·하천 강경계가 있는지를 보고 병합 여부를 판단한다. 4m는 법정 가로구역 기준이 아니라 초기검토 엔진 운영기준이다.
- 사업별 Rule 연결 예: 역세권활성화/역세권복합개발 4m·8m, 주택재개발 6m 접도율, 성장잠재권 35m·6m, 장기전세 간선도로, 도심복합개발혁신지구 20m·8m 등. 도로기능(주·보조간선 등)이 필요한 제도는 폭원만으로 기능을 확정하지 않는다.

- **민간주택개발:** 주택개발사업
- **특례 주택사업:** 안심주택 / 상생주택 / 역세권 장기전세 / 도심 공공주택 복합사업
- **도심정비사업:** 도시정비형 재개발 / 역세권활성화 / 성장잠재권활성화 / 도심복합개발혁신지구 / 역세권복합개발 지구단위계획
- **특례개발사업:** 도시계획변경 사전협상 / 도시혁신구역 / 도시계획시설입체복합구역 / 복합용도구역

실제 자동 판정모듈은 **15개**입니다. 소규모주택정비는 하나의 Family 모듈 안에서 4개 법정사업과 `모아타운+모아주택` 정책·관리계획 추진경로를 각각 분리해 보여줍니다. 모아타운+모아주택은 제5의 법정 소규모정비사업으로 판정하지 않고, 실제 시행방식은 자율·가로·소규모재건축·소규모재개발 중 해당 사업으로 연결합니다.

도시혁신구역·도시계획시설입체복합구역·복합용도구역은 대상지를 단순 정량조건으로 자동 활성화하기 어려우므로 **추후보완예정 shell**로 표시하며 추천·우선순위·시뮬레이션에는 넣지 않습니다. 도시계획변경 **사전협상은 독립 검토모듈**로 운영합니다.

모든 독립 검토모듈의 검토결과와 계획기준 표는 **근거유형 / 공식 근거명 / 조문·장절 / 기준일 / 원문 링크**를 같은 형식으로 표시합니다. 근거가 불명확하거나 최신 원문을 확정하지 못한 항목은 자동 PASS하지 않고 `REVIEW`로 유지합니다.

### 사업 Family 분리 원칙

- **주택정비사업:** 연속지적·건축물대장·정비구역·면적·과소필지·호수밀도·제도별 접도 등 원자료 Fact만 공유하고, 입안요건·노후도·시행방법은 각 Rule Module이 독립 판정합니다.
- **소규모주택정비사업:** 동일 원자료를 공유하되 자율·가로·소규모재건축·소규모재개발 기준을 섞지 않습니다. 모아타운·관리지역은 법정사업의 요건을 바꾸거나 추진경로를 보완하는 서울시 정책·관리계획 상태로 별도 표시합니다.
- **민간주택개발:** 주택정비사업의 노후도·과소필지·주택접도율을 진입조건으로 사용하지 않고 `용도지역 → 도시계획 제한 → 계획 주택규모/유형 → 주택법 사업계획승인 또는 건축법상 허가 → 설계조건` 순으로 검토합니다. 정비사업 미달의 fallback으로 자동 PASS시키지 않습니다.
- **특례 주택사업 / 도심정비사업 / 특례개발사업:** 각 법률·조례·운영기준·기본계획을 독립 적용하고 공통 Boolean으로 합치지 않습니다.

### 구역계 입력·검토 흐름

기존 지번입력과 지도 직접그리기를 유지하고 **SHP ZIP 구역계 입력**을 추가합니다. 지도는 `일반지도 / 항공사진 / 항공사진+도시계획`을 선택할 수 있고, 용도지역·도시계획시설 오버레이의 투명도를 조절할 수 있습니다. 항공사진·WMS 오버레이는 **구역계 작성 보조 시각자료**이며 판정은 공식 벡터 Fact를 별도로 조회합니다.

구역계 입력과 공식 분석을 분리합니다. 구역계를 그리거나 지번·SHP로 설정하면 도형면적을 즉시 표시하고 `검토하기` 버튼을 활성화합니다. 실제 연속지적·건축물·도시계획·도로·사업판정은 사용자가 `검토하기`를 누른 뒤 실행합니다. 외부 API 단계마다 시간제한을 두어 하나의 API가 지연되더라도 검토 버튼이 영구 잠기지 않으며, 미확보 자료는 `REVIEW`로 남깁니다.

- 재개발 주택접도율은 `6m 이상 도로 + 대지경계 연속 4m 이상 접도` 여부를 필지별로 확인하고 해당 필지의 건축물 수를 집계해 개략 산정합니다.
- 동일 도로중심선 원자료를 사용하더라도 역세권활성화·안심주택·성장잠재권·장기전세 등은 각 제도별 도로 Fact를 독립적으로 생성합니다.
- 도로기능(주간선·보조간선·특별시도 등)은 폭원으로 추정하지 않으며 공식 기능자료가 없으면 `REVIEW`입니다.
- **표시되는 접도율은 사업진입조건 확인을 위한 개략적 추정치로, 현장조서 및 도면검토를 통해 보완될 수 있습니다.** 따라서 개략 접도율만으로 법정요건을 최종 확정하지 않습니다.

도로중심선 또는 `ROAD_BT`를 조회하지 못하면 접도율은 임의 추정하지 않고 `REVIEW`로 남깁니다.

## 관리자·이용통계·오류신고

회원가입 없이 브라우저별 익명 방문자 ID와 세션 ID를 발급합니다. 자동분석 완료 시 분석번호와 주소·PNU·면적·필지수·추천결과를 기록해 어떤 대상지가 검토되는지 확인할 수 있습니다. 오류신고에도 같은 분석번호가 붙어 관리자 화면에서 원 분석과 연결됩니다.

- 저장하지 않음: 이름, 원문 IP, 원본 구역계
- 오류신고 연락처: 사용자가 답변을 원해 직접 입력할 때만 저장
- `DATABASE_URL` 있음: PostgreSQL 영구저장
- `DATABASE_URL` 없음: 재시작·배포 시 삭제되는 메모리 임시저장
- 관리자 주소: `/admin`
- 관리자 사용자명: `admin`
- 관리자 암호: `ADMIN_PASSWORD`

무료 배포라도 장기 통계를 유지하려면 PostgreSQL과 `DATABASE_URL`이 필요합니다. 관리자 암호를 소스코드에 직접 쓰지 마십시오.

## v2.5 사업별 독립 검토모듈 구조

판정은 `공통 현황 Fact Store → 사업별 추가 현황체크 → 사업별 독립 Rule Module → 상세 기초검토서 → 사업우선순위` 순서로 처리합니다. 사업모듈은 현황 GIS/API를 제각각 다시 조회하지 않고 동일한 현황 스냅샷을 사용합니다. 특정 사업만 필요한 공간조건은 해당 사업의 추가 현황체크에서 생성합니다.

현재 독립 판정모듈은 **15개**이며, 소규모주택정비는 5개 사용자 검토경로로 세분화하고 사전협상을 독립모듈로 포함합니다. 각 상세팝업은 `현황 / 검토결과 / 계획기준·사업구조·추진조건 / 추진일정` 구조로 표시하고, 검토행과 계획행 모두 공식 근거유형·기준일·조문/장절을 표시합니다. 도시혁신구역·도시계획시설입체복합구역·복합용도구역은 `추후보완예정` shell로 유지합니다.

건축물 노후도는 공통 `OLD/NOT_OLD` 값으로 사업판정하지 않습니다. 공통 건축물 현황에는 사용승인일·구조·용도·연면적 등 원자료만 저장하고, `도시계획계 / 도정법계 / 안심주택 / 역세권 장기전세 / 소규모주택정비 / 도심복합개발 / 도심 공공주택 복합사업` 등 제도별 파생현황을 별도로 계산합니다. 각 사업모듈은 자기 근거에 해당하는 노후도 Fact만 호출합니다.

첫 화면 **공간현황**에는 `제도별 노후도 현황`과 `사업별 추가 현황` 박스를 둡니다. 사업별 추가 현황은 독립모듈의 `collectFacts()`가 Fact Store에 먼저 등록한 데이터만 표시하며, 상세팝업에서 새로운 현황값을 임의 생성하지 않습니다. 이후 안심주택 의료시설 350m 범위 등 특정 사업에만 필요한 공간조건도 같은 구조로 추가합니다.

첫 화면의 좌우 배분구조는 유지하면서 우측 하단에 **선순위 사업 미리보기**와 향후 **위치기반 매스 이미지**를 연결할 프로토타입 영역을 두었습니다. 매스 이미지는 현재 버전에서 생성하지 않습니다.

## 공간현황 근거데이터

v2.5.0의 공간현황은 판정결과의 근거화면입니다. 핵심 현황도에는 동일 연속지적·선택필지 경계를 공통 베이스로 표시하며, 용도지역 현황·제도별 도로기준·안심주택 의료시설 현황을 별도 도면으로 제공합니다. 도로는 원자료 폭원과 사업별 적격기준을 분리합니다. 의료시설은 공개 위치점 자체를 PASS 근거로 사용하지 않고, 위치점 및 공식 인허가 지번주소를 앵커로 복원한 `도시계획시설 종합의료시설 경계 / 건축물대장 총괄표제부·표제부 + 부속지번 지적경계 / 보건소 최신 위치점 소재필지 경계` 중 확정된 부지경계와 350m 버퍼를 동일 Fact로 지도와 안심주택 엔진이 공유합니다. 2023 보조 위치자료는 참고도형만 허용하고 자동 PASS를 금지합니다.

### r20 프로토타입 안정화·분석상태 진단

- 노선형 상업지역은 도로자료 또는 도로명 속성이 없을 때 `후보 없음`으로 확정하지 않는다. 원자료 미확보와 실제 비해당을 구분한다.
- `사업별 추가 현황`은 데스크톱에서 전체 폭 3열 카드로 표시해 세로 스크롤을 줄였다.

## r33 사업구역 통합폴리곤 보정 (2026-09-04)
- `사업구역·가로구역 검토` 제목과 가로구역 분리 로직은 유지합니다.
- 가로구역 후보를 분리한 뒤 `가로구역 원형(rawBlocks) + 사이 가로망·분할시설(sepUnion)`을 다시 합쳐 상위 `project_area` 통합폴리곤을 생성합니다.
- 쿨데삭형 내부 가로망은 가로구역 면에서는 홈으로 보일 수 있지만, 사업구역계에서는 해당 가로망을 다시 포함해 닫힌 외곽면으로 표시합니다.
- 검토요청지(`requestArea`)와 통합 사업구역(`projectArea`)을 별도 Fact로 보존하며, 사업구역 근거는 `street_blocks_plus_internal_network`로 기록합니다.
- 붉은 2점쇄선 사업구역계를 최종 렌더 순서에서 앞으로 올려 검토요청지·가로구역 선에 가려지지 않게 했습니다.
- 이 기능은 계속 공간 FACT 검증용이며 기존 사업 Rule 엔진에는 아직 연결하지 않습니다.

## r35 사업구역·가로구역 완전 분리 (2026-09-04)
- r32에서 실제 사례로 정상 확인된 가로구역 분할 로직을 동결했습니다. 가로구역은 검토요청지와 교차하는 지적도로, ROAD_BT 4m 이상 도로면, 도시계획시설 separator만으로 독립 계산하며 사업구역 결과를 입력으로 사용하지 않습니다.
- 사업구역은 `buildIndependentProjectAreaCandidate()`에서 별도 계산합니다. 검토요청지와 원천 도로·도시계획시설 FACT의 공간관계를 직접 사용하며 `street_blocks` 또는 가로구역 separator 결과를 참조하지 않습니다.
- 사업구역에서는 경계부 외곽도로·시설만 외곽 절단 후보로 보고, 내부 관통도로·쿨데삭·가로구역 사이 내부 가로망은 면 내부에 포함하여 하나의 폐합된 사업구역 후보 폴리곤을 유지합니다.
- 사업구역과 가로구역은 같은 원천 FACT를 각각 읽을 수 있으나 서로의 결과값을 전달하지 않는 구조로 분리했습니다.
- 이 화면은 계속 공간 FACT 검증용이며 기존 사업별 RULE 엔진에는 아직 연결하지 않습니다.
