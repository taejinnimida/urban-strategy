[2026-08-27 · 사업별 독립 검토모듈 아키텍처 전환]
- 판정 흐름을 `공통 현황 Fact Store → 사업별 추가 현황 → 사업별 독립 Rule Module → 사업별 검토서 → 장단점 기반 우선순위` 구조로 전환하기 시작함.
- 역세권활성화사업을 첫 독립 모듈로 이관. 나머지 13개 사업은 서비스 연속성을 위해 legacy-adapter로 유지하며 사업별 검토서 확정 순서대로 교체하도록 구조화.
- 역세권활성화 전용 facts는 대상지 면적·용도지역·역세권·중심지·실폭도로·정비구역·재정비촉진·도시계획시설·노후도·사전협상 여부를 현황분석 결과에서 읽도록 구성.
- 역세권활성화 판정에서 역세권/간선도로변을 별도 검토 후 OR 결합하고, 도로요건은 `4m 이상 접면 2면 + 8m 이상 1면`으로 판정.
- 정비구역·촉진지구·도시계획시설은 기존 공간현황도와 동일한 중첩결과를 사용. 특성관리지구·소규모정비 승인자료 등 미연결 현황은 PASS로 추정하지 않고 REVIEW 처리.
- 1,500~10,000㎡ 밖의 대상지는 지원자문단 인정 가능성을 REVIEW로 유지하고, 도시정비형 재개발 방식 30,000㎡ 초과만 명시적 면적 FAIL 처리.
- 5,000㎡ 이상은 면적만으로 사전협상 대상이라 확정하지 않고, 사전협상 협상대상지요건 해당 여부를 별도 게이트로 분리.
- 역세권활성화 상세팝업을 `입안 가능성 / 1. 현황 / 2. 검토결과 / 3. 계획기준 / 4. 추진일정`의 표형 기초검토서로 개편.
- 첫 화면 기존 좌우 배분구조를 유지하고 우측 하단에 `선순위 사업 미리보기 + 위치기반 매스 이미지(프로토타입 자리)`를 추가.
- 사업우선순위 엔진이 사업모듈의 strengths / risks / followups를 읽도록 연결. REVIEW(위원회·지원자문단·자료보완)는 명백한 FAIL과 구분하여 조건부 후보로 유지.
- 회귀검사에서 정비/개발/도로 대형 STRtree 캐시를 단계별 해제하도록 개선하여 전체 검사 연속실행 메모리 지연을 해소.
