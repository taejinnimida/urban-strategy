# 전국 도시정보플랫폼 — 4. 자연환경조사 도면·통계표·보고서 자동생성 개발 작업지시서

기준일: 2026-11-10
대상 저장소: `taejinnimida/urban-strategy`
기준 브랜치: `feature/nature-survey-tables-20261110` (기존 3번 건축물현황 작업 브랜치를 포함)
권장 신규 작업 브랜치: `feature/nature-drawings-report-20261110`

## 0. 작업 목적 및 범위

확정된 대상지 구역계를 기준으로 **4-1~4-8 자연환경조사**의 공식 원자료를 수집·검증하고, 동일 FACT에서 **현황분석도면 + 통계표 + 분석 서술문**을 생성한다. 결과는 웹에서 검토하고 SVG·DXF(실제 벡터가 확보되는 경우만)·XLSX·편집 가능한 HWPX 보고서에 재사용할 수 있게 설계한다. 단순 현황조회 화면의 완성은 최종 성과품 완료와 다르다.

기존 `main` 운영판과 서울도시정비 RULE은 **절대 수정·자동 배포·병합하지 않는다.** 기존 기능을 전체 재작성하거나 서울 정비사업 코드를 전국 제도에 복사하지 않는다. 작업 시작 전에 저장소 최신 커밋과 각 모듈의 실제 데이터 구조를 점검하고, 최소 변경·별도 개발 브랜치·초안 PR로 진행한다. 사용자 확인 전에는 운영 브랜치에 병합하지 않는다.

## 1. 우선 확인할 실제 코드와 현재 한계

- `development_sources.py`: DEM(표고·경사·동서/남북 단면), 공식 등록 파일, 생태·자연도 WFS, 국토환경성평가 WMS, ASOS 등 수집 흐름. DEM 지도용 반환 도형은 최대 5,000개까지 제한되므로 **지도용 도형 일부를 전체 통계로 오인하면 안 됨**.
- `development_ecobank.py`: 4-3 생태·자연도 WFS 분류·등급·면적과 `EPSG:5186` 집계값. 최신 법정 고시도면 확인과는 별개임.
- `development_nature_tables.py`: 4-1~4-8의 일부 요약표와 보수적 분석문은 이미 존재하나 **표고·경사 구간별 면적표, 실질적인 전용 도면 생성, HWPX 편집 보고서 삽입**은 완성되지 않음.
- `development_cad.py`, `development_survey_sheet.py`: 기존 A3 양식과 EPSG:5179 실좌표 DXF 및 SVG 출력기. 4번 자연환경 전체를 새로 지원하지는 않음.
- `development_report.py`: `survey_table` 및 `자연환경현황표` XLSX 출력 연결.
- `development-ui.js`: 4번 통계표·분석문 조회는 연결되어 있으나 분석도면의 출력·미리보기는 항목별로 완성되지 않음.

**코드 검사 없이 이미 구현된 것으로 간주하지 말 것.** 현재 PR #1은 건축물현황, PR #2는 자연환경 요약통계 작업이며 모두 개발 초안이다.

## 2. 모든 항목에 적용할 일관된 데이터 계약

각 항목마다 서버가 아래의 *하나의 정규화된 결과 객체*를 제공한다. 독립적인 화면 통계 재계산은 금지한다.

- `item_id`, `title`, `source_provider`, `source_url`, `source_as_of`, `queried_at`, `crs`, `unit`, `boundary_revision`, `fact_revision`
- `source_status` (공식 원자료 직접 확보/부분 확보/WMS 도면 전용/미등록/조회 오류/적용범위 밖/추가 확인 필요), `analysis_status` (완전/잠정/미산정)
- `site_area_m2`, `mapped_union_area_m2`, `valid_area_m2`, `unclassified_area_m2`, `coverage_gap_m2`, `overlap_area_m2` — 산정 가능한 항목만
- `classes[]`: `class_code`, 원자료 분류명 또는 명시된 설명용 구간, 색상, 건수, 면적, 구성비, 결측/미분류 여부
- `summary_metrics`, `map_features_or_raster`, `analysis_text`, `notes[]`, `limitations[]`

동일 FACT가 웹 지도·도면·표·XLSX·HWPX에 공급되도록 하고, 화면에서 면적·구성비·건수 재산정하지 않는다. 데이터가 없으면 `null/미확보`이며 0·없음·비해당으로 대체하지 않는다. 실제 자료가 **정상적으로 0건 응답한 것**과 **API 오류**는 반드시 구분한다. 공간 집계 시 영역을 먼저 구역계로 절단(clipping)하고 중첩·누락·좌표계 오류를 검증한다. 면적 계산에는 명시된 미터 기반 좌표계를 사용한다. 출력값 소수자리 반올림 때문에 합계와 차이가 나면 원값 기준 계산과 표시용 값의 차이를 각주로 표시한다.

## 4. 도면 공통양식 및 출력

- **기존** `development_survey_sheet.py`와 `development_cad.py`의 도곽·A3 종이공간·방위·축척·확장 지적 배경·EPSG:5179 체계를 가능하면 재사용한다.
- 각 도면: 도면번호, 정확한 도면명, 대상지 구역계(강조), 적절한 배경지적·주요 공간요소, 범례, 방위표, 실제 거리기반 축척, 자료출처, 자료 기준일, 작성일, 집계상태/미확보 주석.
- 보고서의 SVG 또는 렌더 이미지와 통계표가 **동일 FACT·동일 분류·동일 기준일**을 참조해야 한다.
- 원자료가 벡터인 경우 실제 평면좌표를 보존한 DXF 출력 가능; 래스터 원자료는 이미지+좌표정보로 별도 출력하고 DXF의 실도형처럼 허위 표시하지 않는다.
- 지형단면은 단면선의 시작/끝 좌표, 거리축(m), 표고축(m), 높이 과장비(존재한다면) 등을 함께 표기한다.
- 원자료가 미확보된 경우 실제 도형을 그리는 척하지 않는다. 지도 미리보기 영역에 자료상태 및 원자료 등록·재조회 사유를 표시한다.

## 5. 보고서 작성 및 편집 기준

**보고서 이름:** `도시계획 현황 분석보고서`  
**장 제목:** `4. 자연환경현황` (화면·엑셀의 기존 항목명과 일치)

각 소절은 `소절 제목 → 자료 기준/확보상태 → 도면(해당 시) → 현황표 → 정량 분석문 → 계획적 시사점(확인 사실만) → 출처·한계 주석` 순서다. 숫자는 표의 **원 FACT에서** 가져오고 임의의 입지 적합성·사업성 판정을 문장에 끼워 넣지 않는다. 통계·표고·경사 수치는 소수 둘째 자리, 구성비는 소수 첫째 자리, 도형수·유효일수는 정수로 표시한다.

보고서는 추후 도면/표/문장을 재수정할 수 있도록 **편집 가능한 HWPX**를 1차 목표로 한다. HWPX 패키지 규격과 실제 한글 편집/열기 호환성을 검증할 것. 변환 실패·호환성 미검증 상태에서 ‘보고서 완성’으로 표시하지 않는다. 편집 가능한 HWPX와 단순 읽기용 PDF·이미지를 혼동하지 않는다. 4번 단독 미리보기나 HTML 출력물을 만들더라도 HWPX 대체완료로 보고하지 않는다.

## 6. 구현 순서 (각 단계별 실제 코드·테스트 증빙 필수)

1. **원자료·계약 검증:** 4-1~4-8의 확보/미확보 현황과 각 FACT 필드·좌표계/날짜 확인. 누락·중복·자료기준일 불일치 기록.
2. **정량분석:** DEM 동일 셀 기반 표고·경사 분류면적, 생태/산림/수계의 중복·미분류·합집합 처리, 관측 유효일수·단면 유효표본. 서버 측 단일 파생 FACT 구축.
3. **분석도면:** 4-1/4-2 주제도, 4-3~4-6 원도형 현황도, 4-7 관측소(가능시), 4-8 단면선/단면그래프. 기존 도곽/범례 적용.
4. **표·서술문:** `survey_table` 또는 호환되는 공통 FACT를 이용해 동일 집계값·한계·출처를 웹/XLSX로 연결.
5. **보고서:** HWPX 삽입 및 장별 자동편집. 지도·표·문장 불일치 자동 검사.
6. **실증:** 실제 대상지 최소 1곳에서 자료조회→도면→표→보고서 다운로드/열기와 회귀 테스트. 현장 결과 없는 경우 미완료 표기.

## 7. 필수 자동검증 및 수용 기준

- Python/JavaScript 문법 및 FastAPI 라우트, 기존 서울 정비사업 기능 회귀 오류 없음.
- 4-1/4-2 구간 경계값(0,5,10,15,20°와 0,20,40,60,80m), 음수 표고, NoData, DEM 경계셀, Horn 3×3 부족, 지도용 5,000도형 제한을 각각 검증.
- 지도색 범례·도형 분류·통계표 구간 및 면적이 동일하며, 분류면적과 합집합/결측/중첩이 대조 가능.
- 4-3 WFS 검증값과 도면·표 일치; 등급 미확보/빈 WFS 응답/조회 실패 차등 표현.
- 4-4 WMS만 확보된 경우 면적 0으로 생성하지 않고 실제 분류표는 ‘미산정’으로 표시. DXF 벡터 출력 금지.
