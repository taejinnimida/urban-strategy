# 서울 도시정비플랫폼 Web MVP v2.5.0

## v2.5.0 drawing 회귀복구

- 공간현황 렌더러가 초기화되지 않은 Fact/cache를 drawing event 등록 전에 호출하던 시작 순서를 수정해 지도 구역계 그리기·편집·삭제 이벤트를 복구했습니다.
- 구형 수기 `역세권·도심복합 사업방식 비교 검토 시트`는 사용자 화면에서 제거하고 엔진 호환용 hidden DOM state만 유지합니다.
- 도로는 `road_raw` 원자료와 제도별 파생 Fact를 분리합니다. `20m 이상 도로`는 폭원 후보일 뿐 공통 간선도로 판정이 아니며, 도로기능 자료가 없으면 해당 제도는 `REVIEW`입니다.
- 용도지역 현황은 `LT_C_UQ111`의 용도지역별 면적·구성비를 표시하고, 안심주택 의료시설은 부지경계 미확보 시 위치점 참고만 제공하여 자동 PASS하지 않습니다.

## v2.5.0 공간현황·사업별 독립 검토엔진 보완

- 기존 토지·건축물·역세권·중심지 도면을 유지하고 `정비사업 관련 현황도`와 `도시계획·개발사업 현황도`를 독립 도면으로 추가했습니다.
- 정비사업 현황도는 기준 배포본의 서울 `UQ181` 법정구역과 `UQ120` 사업·후보구역을 서버에서 실제 공간중첩합니다. 전체 구역경계는 옅게, 대상지 중첩부분은 진하게 표시하며 주택정비형·도시정비형·재건축·재정비촉진·기타 정비를 구분합니다.
- 도시계획·개발사업 현황도는 VWorld 지구단위계획구역과 기준 배포본 `UQ181`의 도시개발구역·공공주택지구·기타 법정 사업구역을 구분합니다. SHP 미응답을 `중첩 없음`으로 오판하지 않습니다.
- 안심주택 입지는 서울시 공식 `서울특별시 안심주택 건립 및 운영기준`(2026-08-03 제2차 개정)에 따라 `역세권 / 간선도로변 / 의료시설 중심지역`을 각각 판정합니다.
- 역세권은 승강장 경계 250m를 기본경로로 판정하며, 250~350m는 운영기준상 예외 검토구간으로 `REVIEW` 처리합니다. 지구단위계획구역 중첩을 역세권 필수요건으로 임의 추가하지 않습니다.
- 간선도로변은 실폭도로에서 폭 20m 이상·50m 이내 후보를 찾되, 특별시도 여부·주간선/보조간선 기능·도시고속도로 제외를 확정할 결합자료가 없으면 `PASS`하지 않습니다.
- 의료시설 중심지역은 종합병원·서울시 관리 시립병원·보건소를 구분합니다. 종합병원·시립병원은 `LOCALDATA_010101`, 보건소는 매일 갱신되는 의원 인허가 `LOCALDATA_010102`를 우선 사용하고 실패 시 2023 시설물 자료를 위치 참고용으로만 보조조회합니다. 공개 위치점은 후보검색에만 사용하고 법정 `의료시설 대상부지 경계 350m`를 확인할 수 없으면 `REVIEW`입니다. 의료시설 경로는 임대주택 100% 어르신 공급 조건을 함께 확인합니다.


## v2.5.0 독립 검토모듈 9종

현재 `공간현황 Fact Store → 사업별 추가 현황 → 독립 Rule Module → 전용 검토서 → 우선순위` 구조로 이관된 사업은 다음 9종입니다.

- 역세권활성화사업
- 성장잠재권 활성화사업
- 안심주택
- 상생주택
- 역세권복합개발 지구단위계획
- 역세권 장기전세주택
- 도심 공공주택 복합사업
- 도심복합개발혁신지구
- 도시정비형 재개발사업

역세권 장기전세의 최대 700% 특례는 `승강장 경계 250m 이내` 또는 `지역중심 이상 2개 노선 이상 환승역세권 350m 이내`를 입지후보로만 자동 확인하고, 활성화 필요성 및 위원회 인정 전에는 계획용적률로 확정하지 않습니다. 도심 공공주택 복합사업은 서울 세부기준의 350m·20년 이상 60% 기준을 적용하며 관련 규정의 2026-12-31 유효기간과 경과조치를 별도 표시합니다. 도시정비형 재개발의 독립 진입은 `정비구역 / 정비예정구역 / 정비가능구역`으로 구분합니다. 정비가능구역은 공식 범위 포함을 먼저 확인한 뒤 용도지역·최소면적·노후도 조건을 적용하며, 정책사업의 법적 시행방식으로 사용되는 경우 별도 추천사업으로 중복 집계하지 않습니다.

## v2.4.3 서울 실폭도로 내장

- 2026년 8월 서울 공식 도로명주소 실폭도로 `TL_SPRD_RW` 60,534건을 `road_seoul.zip`으로 내장했습니다.
- 좌표계 `EPSG:5179`를 자동 인식해 대상지 60m 범위의 도로만 서버에서 반환합니다.
- VWorld Data API를 먼저 조회하고, 미응답 시 내장 원본으로 자동 전환합니다.
- 원본은 폭원 속성이 없는 실폭 폴리곤이므로 공식 도형에서 폭을 산정하고, `6m 이상 도로 + 대지경계 연속 4m 접도`를 자동 계산합니다.
- 일반 사용자는 도로 SHP를 별도로 다운로드하거나 업로드할 필요가 없습니다.

## v2.4.2 주택재개발 판정 보정

- 신규 주택재개발 입안은 `구역면적 AND 노후도 AND 추가 입안요건 1개 이상`을 모두 충족해야 후보·순위·시뮬레이션에 진입합니다.
- 추가 입안요건이 모두 미달하고 접도율만 미확인인 경우 `접도율 확인 전 보류`로 표시하며 추천에서는 제외합니다.
- VWorld `TL_SPRD_RW`·`TL_SPRD_MANAGE` Open API 조회가 성공하면 `6m 이상 도로 + 연속 4m 접도`를 필지·건축물 단위로 자동 산정해 주택접도율에 반영합니다.
- 기정 주택정비형 정비구역 SHP 중첩 시 신규 입안요건 대신 해당 결정고시·정비계획 경로를 우선합니다.
- 사업방식 상세 팝업에 근거 종류, 법령·조례명, 조문·장·절, 기준일, 공식 원문 링크를 행별로 표시합니다.

서울 대상지의 주소를 입력하거나 구역계만 그리면 토지·건축물·역세권·중심지·도시계획을 자동 분석하고 14개 정비·개발사업을 비교하는 초기검토 플랫폼입니다.

## v2.4.0 핵심 변경

- 등록된 14개 사업카드 중 현재 독립엔진이 완성된 9개 사업은 판정행마다 `근거유형 / 기준일 / 조문·장·절 / 대상지 값 / 부족값 / 다음 조치 / 대안 / 신뢰등급`을 연결합니다. 나머지 5개는 구형 판정엔진을 삭제하고 shell-only 상태로 유지합니다.
- 근거를 법률·시행령·조례·운영기준·기본계획·지침으로 구분했습니다. 최신 원문을 확보하지 못한 기준은 `PASS`를 금지하고 `REVIEW`로 낮춥니다.
- 면적을 법정 하드게이트로 분리했습니다. 미달 사업은 결과 카드에 사유를 남기되 추천 1·2·3순위와 계획규모 시뮬레이션에는 포함하지 않습니다.
- 명시적 심의·지원자문단 예외가 있는 면적은 `REVIEW`로 남기지만, 예외 인정 전에는 추천하지 않습니다.
- 안심주택은 기준 ZIP 수록 2025-08-13 개정 운영기준에 따라 최소 1,000㎡, 자연녹지·1종일반주거의 어르신 100%·5,000㎡ 특례, 용도지역 변경 및 인접·도로조건을 구분 판정합니다.
- 장기전세 간선도로 교차지역은 `교차지 도로경계 200m 이내 + 구역둘레 1/8 이상 20m 도로 접면`을 함께 판정합니다.
- 역세권활성화·역세권복합개발·소규모주택정비의 정비구역 배타관계를 공식 SHP 중첩값과 연결했습니다.
- 소규모주택정비를 소규모재건축·소규모재개발·가로/자율주택정비 후보로 우선 분기하고, 면적·노후도·도로·기존 세대수의 확인항목을 표시합니다.
- 시뮬레이션의 종전 `수기 적용용적률`을 `계획용적률`로 정리했습니다. 기본값은 확보 가능한 법적상한→상한→허용→기준의 최대 시나리오이며, 적용조건과 공식 근거를 바로 아래 표시합니다.
- 분석마다 `분석번호`를 발급합니다. 오류신고에 분석번호·주소·PNU·면적·추천결과를 자동 첨부하고 관리자 화면에서 분석기록과 신고를 연결합니다.
- 화면 상단에 **⚙ 관리자** 아이콘을 고정하고, `접수 / 확인 중 / 처리완료` 상태를 관리합니다.

- 관리자 화면에서 익명 방문·분석 대상지·추천결과·오류신고와 처리상태를 확인합니다.

## 실폭도로·접도율 자동화

플랫폼은 `TL_SPRD_RW` 실폭도로와 `TL_SPRD_MANAGE` 도로구간을 이용해 다음을 계산합니다.

- 도로 폭원
- 폭 6m 이상 도로 여부
- 대상지 접면 도로 수, 최대 폭원, 폭 8m 이상 도로 및 폭 20m 도로 접면비율

## 관리자·이용통계·오류신고

회원가입 없이 브라우저별 익명 방문자 ID와 세션 ID를 발급합니다. 자동분석 완료 시 분석번호와 주소·PNU·면적·필지수·추천결과를 기록해 어떤 대상지가 검토되는지 확인할 수 있습니다. 오류신고에도 같은 분석번호가 붙어 관리자 화면에서 원 분석과 연결됩니다.

- 저장하지 않음: 이름, 원문 IP, 원본 구역계

- `DATABASE_URL` 없음: 재시작·배포 시 삭제되는 메모리 임시저장
- 관리자 주소: `/admin`
- 관리자 사용자명: `admin`
- 관리자 암호: `ADMIN_PASSWORD`

무료 배포라도 장기 통계를 유지하려면 PostgreSQL과 `DATABASE_URL`이 필요합니다. 관리자 암호를 소스코드에 직접 쓰지 마십시오.

## v2.5 사업별 독립 검토모듈 구조

판정은 `공통 현황 Fact Store → 사업별 추가 현황체크 → 사업별 독립 Rule Module → 상세 기초검토서 → 사업우선순위` 순서로 처리합니다. 사업모듈은 현황 GIS/API를 제각각 다시 조회하지 않고 동일한 현황 스냅샷을 사용합니다. 특정 사업만 필요한 공간조건은 해당 사업의 추가 현황체크에서 생성합니다.

현재 독립 이관 모듈은 **역세권활성화사업, 성장잠재권 활성화, 안심주택, 상생주택, 역세권복합개발 지구단위계획, 역세권 장기전세주택, 도심 공공주택 복합사업, 도심복합개발혁신지구, 도시정비형 재개발**의 9개입니다. 각 상세팝업은 `입안·추진 가능성 / 현황 / 검토결과 / 계획기준 / 추진일정` 구조로 표시합니다. **주택재개발·재건축·주거환경개선·소규모주택정비·일반 주택건설사업은 구형 판정엔진을 모두 삭제하고 카드·팝업 껍데기만 유지하며, 새 검토서가 확정될 때까지 추천·우선순위·시뮬레이션에 진입하지 않습니다.**

건축물 노후도는 공통 `OLD/NOT_OLD` 값으로 사업판정하지 않습니다. 공통 건축물 현황에는 사용승인일·구조·용도·연면적 등 원자료만 저장하고, `도시계획계 / 도정법계 / 안심주택 / 역세권 장기전세 / 소규모주택정비 / 도심복합개발 / 도심 공공주택 복합사업` 등 제도별 파생현황을 별도로 계산합니다. 각 사업모듈은 자기 근거에 해당하는 노후도 Fact만 호출합니다.

첫 화면 **공간현황**에는 `제도별 노후도 현황`과 `사업별 추가 현황` 박스를 둡니다. 사업별 추가 현황은 독립모듈의 `collectFacts()`가 Fact Store에 먼저 등록한 데이터만 표시하며, 상세팝업에서 새로운 현황값을 임의 생성하지 않습니다. 이후 안심주택 의료시설 350m 범위 등 특정 사업에만 필요한 공간조건도 같은 구조로 추가합니다.

첫 화면의 좌우 배분구조는 유지하면서 우측 하단에 **선순위 사업 미리보기**와 향후 **위치기반 매스 이미지**를 연결할 프로토타입 영역을 두었습니다. 매스 이미지는 현재 버전에서 생성하지 않습니다.
