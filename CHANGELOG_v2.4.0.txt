도시검토 플랫폼 v2.4.0 변경 로그
기준일: 2026-08-26

1. 라이브 장애 복구·배포 안정화
- GitHub 웹 업로드로 static/data 폴더가 평면화되어도 app.html과 공간자료를 찾도록 수정.
- /health에 asset_layout과 asset_files_ready 추가.
- 파일 누락 시 원인을 알 수 있는 503 오류문구 추가.

2. 14개 사업방식 판정감사 구조
- 판정행마다 자료유형, 기준일, 조문·장·절, 부족값, 다음 조치, 대안, 신뢰등급 연결.
- 법률·시행령, 조례, 운영기준, 지침, 기본계획을 구분.
- 최신 공식 세부기준 미확인 자료의 PASS를 REVIEW로 자동 하향.
- 자동확정 / 조건부 / 공부·현장 확인의 3단계 신뢰등급 적용.

3. 면적 하드게이트·배타관계
- 최소·최대면적 미충족 사업은 추천 1·2·3순위와 시뮬레이션에서 제외.
- 명시적 예외·자문·위원회 인정경로는 REVIEW로 남기되 인정 전 추천 금지.
- 주택정비형·도시정비형 재개발과 기존 정비구역 유형의 우선·배타관계 보강.
- 역세권활성화, 성장잠재권, 역세권복합개발, 도심공공주택복합사업의 기존 사업구역 제외조건 보강.
- 도심공공주택복합사업에 공공주택 업무처리지침 제20조의3 기존 사업구역 제외 추가.

4. 개별 지적사항 보완
- 안심주택 주거지역을 시장 지정 세부지역 확인 전 REVIEW로 변경.
- 장기전세 간선도로 교차지역에 도로경계 200m 조건 반영.
- 역세권활성화 기준 외 면적을 지원 자문단 인정 전 추천에서 제외.
- 성장잠재권 2026.05.28. 운영기준의 비역세권·35m 도로·면적·동의·용적률 체계 연결.
- 상생주택 3,000㎡ 또는 100세대 기준과 위원회 조정 예외를 분리.
- 최신 서울 세부기준이 확인되지 않은 도심복합개발 세부 입지·면적값은 REVIEW 유지.

5. 경쟁력 있는 결과표현
- 탈락·확인 사유와 기준까지의 ㎡, %p, m, 세대수 차이 표시.
- 공부·현장 확인, 구역계 조정, 기반시설·도로확폭, 다른 사업방식 비교 등 다음 조치 표시.
- 사업별 대체 경로와 전략코멘트 표시.

6. 용적률 시뮬레이션
- '계획용적률' 단정 대신 '최대확보 시나리오'로 명칭 변경.
- 기본값은 법적상한→상한→허용→기준 순으로 선택.
- 상한·법적상한은 조건부이며 확정 계획용적률이 아님을 명시.
- 숫자 바로 아래에 자료유형·기준일·조문/장절·자동입력 근거 표시.
- 최신 세부기준 미확인 사업은 용적률 숫자 자동입력과 밀도순위 가중 금지.

7. 공간현황·도면
- 토지·과소필지·실폭도로, 건축물·노후도, 역세권, 중심지, 도시계획 미니도면 유지.
- 도시계획 도면과 현황에 용도지역·지구, 도시계획시설, 지구단위계획구역,
  정비구역·정비예정구역, 재정비촉진지구·구역 동시 표시.
- UQ181 법정구역 우선, UQ120 사업·후보자료 보조, 3,246개 도형 서버 공간색인 유지.

8. 접도율 GIS
- TL_SPRD_RW 실폭도로 우선.
- 실폭도로 부재 시 도로중심선+공식 폭원 속성 버퍼를 AUTO(예비)로 사용.
- 6m 이상 도로, 총 접도길이, 최장 연속 4m 접도, 건축물 접도율 계산.
- 예비값·도형추정값만으로 법정 PASS 금지.

9. 분석번호·관리자·오류신고
- 화면 상단에 '⚙ 관리자' 아이콘 추가.
- 대상지 분석마다 분석번호 자동발급.
- 분석번호를 통계, 보고서 JSON, 오류신고에 연결.
- 관리자 화면에 분석번호 열 추가.
- 오류신고에 대상지 주소·PNU·면적·추천결과 자동첨부.
- 접수 / 확인 중 / 처리완료 상태관리 유지.
- PostgreSQL 기존 테이블에 analysis_id 컬럼을 안전하게 자동추가.

10. 검증
- Python 컴파일 및 프론트 JavaScript 구문검사.
- 홈 화면, 349개 역사, 76개 중심지, 3,246개 정비구역 자료 로딩 확인.
- 폴더형과 GitHub 평면형 배포를 모두 회귀검사.
- 관리자 아이콘, 분석번호, 하드게이트, 최신자료 REVIEW, 200m 조건, 접도율 GIS 연결을 회귀검사.
